# 接入契约与注册点（通用）

按依赖顺序排列。每节给出“要做什么、验收标准”，不绑定具体工程的文件名或界面框架。

---

## 1. 分层与职责

```
<app>/
├── adapters/<vendor>/
│   ├── loader        # 定位 / 位数 / 同目录依赖 / 导出校验 / 缓存
│   ├── api           # 结构体 + 函数签名 + 常量 + 错误翻译 + 线程安全兜底
│   └── backend       # 实现统一接口，不向上暴露厂商类型
└── ...
```

| 层 | 只做 | 不做 |
| --- | --- | --- |
| loader | 找库、验位数/依赖/导出、缓存句柄 | 业务判断、帧映射 |
| api | 结构体、调用约定、返回值翻译、DLC/模式/锁兜底 | 设备选择、配置读取 |
| backend | 能力校验、字段映射、时间戳归一 | 重复实现驱动兜底、直接操作界面 |
| 业务层 | 只依赖统一接口 | import 厂商 SDK/结构体 |

**验收**：删掉 `<vendor>` 目录后，业务层代码无需修改即可编译；
新增第二个厂商时，不需要改业务层。

---

## 2. 统一后端接口

接口至少覆盖下表能力。方法名可以按语言习惯调整，语义不能变。

| 能力 | 输入 | 输出/异常 | 要点 |
| --- | --- | --- | --- |
| 枚举 | 无 | 设备描述列表 | 身份用 SN；索引只作本次打开；多设备未指定 SN 必须报错 |
| 打开 | 选择项（设备/通道/波特率/FD/只监听） | 成功或分类异常 | 先校验再打开；失败按设备级回滚 |
| 发送 | 通道 + 帧 | 成功/失败 | 拒绝 FD、超 8 字节、只监听通道；不依赖驱动重发 |
| 接收 | 通道 + 批量上限 + 超时 | 帧列表 | 先判队列；失败不产生伪帧；批量上限固定 |
| 状态 | 通道 | 状态快照 | 没有的能力不要伪造 |
| 能力 | 无 | 能力位 | 不确定写 False |
| 关闭 | 无 | 无 | 幂等；逐通道停止/清队列后关设备 |

异常分类建议（至少区分）：

- 库缺失 / 位数不匹配 / 版本或导出不匹配；
- 设备不存在 / 被占用 / 打开失败 / 通道初始化失败；
- 能力不支持（FD、只监听、波特率）；
- 发送失败 / 接收失败 / 设备掉线。

**验收**：上层只根据异常分类决定提示与重试，不需要解析厂商错误码。

## 3. 时间戳契约

- 对外统一单位：**秒**（或明确声明为整数 tick，并给出换算常量）。
- 同通道单调；允许设备侧回绕，但必须在 backend 内展开。
- 区分“总线到达时刻”和“读到时刻”：
  - 有硬件时间戳：用硬件时间戳，并锚定到本机单调时钟；
  - 无硬件时间戳：明确回落读到时刻，并在文档/日志中标注。
- 不要假设首帧为 0；不要跨设备比较绝对时间；只用通道内间隔。
- 判定层不要用“批次读取时刻”当到达时刻；读取补偿只放宽采集，不放宽判定窗口右端。

**验收**：固定周期报文跑 10 分钟，周期统计无负值、无 2 倍/10 倍系统偏差；
跨回绕点（可用注入模拟）仍单调。

## 4. 注册点清单

新增后端时逐项打勾，缺一项都会出现“代码写了但入口看不到/打包后加载失败”。

### 4.1 后端工厂/注册表

- 支持列表加入厂商名；
- 工厂分支延迟 import（避免启动即加载厂商 DLL）；
- 未知后端/加载失败时的降级策略保持原样；
- 支持“强制指定后端”的入口，供设备选择界面逐个枚举。

### 4.2 配置模型

- 新增 `<vendor>_dll_path`（或等价字段），默认空 = 用随包路径；
- 相对路径按应用根目录解析；
- 配置校验：未知后端回退、非法通道/波特率拒绝；
- 环境变量覆盖优先级写清楚（显式配置 > 环境变量 > 随包 > 安装目录）。

### 4.3 默认配置样例

- 增加 `[can.<vendor>]` 段；
- 同步“可选后端”注释；
- 不要在样例里写开发机绝对路径。

### 4.4 设备选择入口（GUI/CLI/服务）

GUI 最少需要：

- 后端下拉：由注册表生成，不硬编码厂商分支；
- 设备表：型号 / SN / 通道数 / 状态；
- 通道号上限：取选中设备的真实通道数；
- FD：不支持的后端自动禁用并清空已勾选；
- 枚举状态分类：驱动缺失、设备未插入、枚举为空、后端未注册；
- 保存/恢复：持久化选择，启动时校验，失效时回退并提示。

CLI/服务模式至少需要：

- `--backend <vendor>`、`--device-sn`、`--channel`、`--bitrate`、`--listen-only`；
- 枚举子命令输出机器可读格式（JSON）；
- 错误码映射为稳定退出码。

### 4.5 诊断与日志

- 启动/打开时记录：DLL 路径、版本、位数、依赖目录；
- 枚举结果、打开结果、错误码、时间戳单位校准结果；
- 发送/接收统计：成功、失败、错误帧、队列峰值。

### 4.6 文档

- 支持设备列表与能力矩阵；
- 驱动安装步骤、VID/PID、是否需要预装运行库；
- 已知限制（不支持 FD、只监听不可发送、时间戳回绕周期等）；
- 第三方库许可与再分发说明。

## 5. 随包运行库与安装包

| 环节 | 要求 | 验收 |
| --- | --- | --- |
| 资源目录 | `resources/<vendor>/` 放主 DLL、同目录依赖与内核驱动子目录（如 `kerneldlls/`） | 目录内文件齐全 |
| 打包前校验 | 主 DLL/依赖 DLL/依赖子目录缺失即失败 | 故意删除一个依赖，打包应报错 |
| 安装清单 | 递归包含整个资源目录 | 安装后文件数与源目录一致 |
| 冻结布局 | loader 同时支持源码目录与可执行目录 | 打包产物能枚举/打开设备 |
| 位数 | 只带目标进程位数；两种位数分目录 | 32 位进程不会加载 64 位 DLL |
| 安装后验证 | 从安装目录启动并打印实际加载路径 | 路径指向安装目录，不是系统旧版 |

不要依赖“把 DLL 放在 exe 旁边就能找到”：同目录依赖、DLL 搜索路径、
打包器的 `contents_directory` 都可能改变实际搜索顺序，加载器要显式处理。

厂商 DLL 可能同名（如旧 ZLG 与创芯都叫 `ControlCAN.dll`）：
按厂商分目录、按绝对路径加载、加载后校验版本并记录解析路径；
不要用文件名做模块缓存键，也不要把多个厂商的 DLL 放在同一搜索目录。

## 6. 测试矩阵

### 6.1 无硬件（必须，CI 可跑）

用假 API/假 DLL 注入，覆盖：

- 结构体大小与字段偏移；
- 波特率/时序表；
- 枚举去重、按 SN 绑定、索引重排；
- 打开失败回滚、重复通道、越界通道、非法波特率；
- FD/超 8 字节/只监听发送被拒且未调用底层；
- 发送字段映射（裸 ID、扩展位、远程位、DLC）；
- 返回值不足/失败 → 异常 + 错误计数；
- 接收失败不产生伪帧、批量上限、等待参数为 0；
- 时间戳回绕展开与倒退钳制；
- 关闭顺序与幂等；
- 并发调用被同一把锁串行化。

### 6.2 有硬件（门控）

- 用环境变量门控（如 `<APP>_<VENDOR>_REAL=1`），默认跳过；
- 只读用例不得调用发送；
- 发送用例带保护：返回值异常、错误码非 0、TEC≥8 任一出现即停止；
- 回归底线：至少一条“实际周期是期望 2 倍必须 FAIL”的断言。

### 6.3 打包

- 打包机与干净机各跑一次；
- 从安装目录启动，确认加载路径、枚举、只读接收；
- 故意缺 DLL 的负向用例必须失败。
